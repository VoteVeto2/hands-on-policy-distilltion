从这里开始

核心思想

各种后训练方法的区别在两点：用谁的样本训练，以及每个样本携带多少反馈。监督微调用别人写的文本训练，学生永远看不到自己的错误。强化学习用学生自己的样本训练，但整条 episode 只换来一个数字。在线策略蒸馏兼取两者之长：学生自己写，更强的教师给每个 token 打分。

方法样本来源反馈本仓库中
监督微调离线策略（教师或数据集）稠密，逐 token未使用
强化学习在线策略（学生自己）稀疏，逐 episode阶段 5
在线策略蒸馏在线策略（学生自己）稠密，逐 token阶段 1–3
蒸馏 + 奖励在线策略（学生自己）稠密 + 稀疏阶段 4

连接这几行的只是一行代数。从学生 p 中采样 yt，把 log q(yt) − log p(yt) 当作奖励。它的策略梯度在期望上恰好等于逐 token 反向 KL，即 KL(p ∥ q) 的梯度。所以蒸馏就是一种强化学习，只不过奖励是稠密的、由教师为每个 token 计算，同一个带截断的策略梯度损失可以服务全部五个阶段。opd/losses_test.py 用数值方法验证了这个等式（test_distillation_advantage_gives_reverse_kl_gradient）。

为什么用反向 KL？因为它是寻模（mode-seeking）的：学生在教师认为不太可能的地方放概率质量会被惩罚，但不会被迫覆盖教师可能说出的所有内容。这很适合无法完整表达大教师的小学生模型。

同一项还会再出现一次。让 RL 策略不偏离起点太远的 KL 惩罚，就是把“过去的自己”当作教师的同一个估计量：ref_kl_coef · (log ref(yt) − log p(yt))，加到优势上。

# opd/trainer.py, update()：每个阶段的核心
advantages = config.loss.reward_coef * batch.task_advantages[:, None]
if batch.teacher_logp is not None:
  teacher_kl = old_logp - batch.teacher_logp          # log p - log q, per token
  advantages = advantages - config.loss.teacher_coef * teacher_kl
per_token, clipped = losses.clipped_policy_loss(
    logp, old_logp, advantages, config.loss.clip_low, config.loss.clip_high)
loss = (per_token * batch.action_mask).sum() / num_tokens

显存都花在哪儿

bf16 下每个参数 2 字节：Qwen3-8B（8.2B 参数）≈ 16.4 GB，Qwen3-1.7B ≈ 3.4 GB。在所有线性层上加 rank 32 的 LoRA 约有 35M 可训练参数；加上 fp32 权重、梯度和 Adam 的两个动量，约 0.6 GB（运行日志会打印确切数量）。全参数微调需要保存 fp32 主权重、梯度和 Adam 状态：每个参数 16 字节，1.7B 模型约 27 GB。Mac 那几行上的虚线是 macOS 默认允许 GPU 使用的份额，约为内存的 75%（36 GB）；斜线填充的“余量”是留给激活值、logits 和 KV 缓存的空间。

代码地图

  1. opd/losses.py：所有阶段的数学，约 150 行。先读它。
  2. opd/rollout.py：一条 episode 如何变成一个带 action mask 的 token 序列。
  3. opd/chat.py：Qwen3 对话格式、工具 schema、工具调用解析。
  4. opd/trainer.py：collate、score、update、train。

每次运行的输出都在 --workdir 下：metrics.jsonl（每步一行 JSON）、samples.jsonl（解码后的 episode，工具结果包在 [env]…[/env] 中）、config.json，以及检查点 step_N/ 和 final/。经常读样本。大多数 RL bug 在曲线上显现之前，就已经能在文本里看出来。

opd/configs/stage1_distill.py

纯在线策略蒸馏

学生回答 GSM8K 小学数学题。教师读每个答案，并对每个 token 报告自己写出这个 token 的可能性有多大。仅此而已：没有奖励，没有工具，损失里也没有参考答案。参考答案只用来衡量留出集上的准确率，所以你可以看到准确率在一个从未提及“对错”的信号下不断上升。

关键参数

loss.reward_coef = 0.0
train.samples_per_prompt = 1
rollout.max_turns = 1
train.lr = 1e-4      # LoRA (Tinker's OPD recipe)

阅读

  • losses.token_logprobs：float32，一次处理一行。
  • trainer.forward_logits：logits_to_keep 跳过提示词位置。
  • trainer.update：优势中的教师项。
  • rollout.generate：采样参数的覆盖，以及为什么要覆盖。
python -m opd.main --config=opd/configs/stage1_distill.py:mps --workdir=runs/stage1

观察

  • ↓teacher_kl：采样 token 上的平均逐 token 反向 KL。这是定义本阶段的那条曲线。

opd/configs/stage2_single_tool.py

单工具智能体蒸馏

现在一条 episode 有多轮。学生写出 <tool_call>，环境执行它并以 <tool_response> 回应，学生继续写。这些回应会进入上下文，但不是学生的动作，所以它们的 action mask 为 0。教师依然给学生的每个 token 打分，包括工具名和 JSON 参数，并以同一上下文中看到的工具结果为条件。

每次实验只用一个工具。每个工具教的东西不同：计算器奖励“知道心算何时会出错”，SQL 奖励“读懂错误信息”，JMESPath 奖励“探索一个你看不到的文档”。

关键参数

env = "calculator"   # or "sqlite", "json"
rollout.max_turns = 4
rollout.max_new_tokens = 256        # per turn
rollout.max_completion_tokens = 1024  # whole episode

阅读

  • chat.encode_prompt：工具的 docstring 变成系统提示词里的 JSON schema。
  • chat.encode_tool_results：为什么 token 总是追加，而从不重新渲染。
  • rollout._step：一轮、它的工具调用、以及 mask。
  • envs/base.call_tool：失败会变成错误信息，而不是崩溃。
python -m opd.main --config=opd/configs/stage2_single_tool.py:mps --config.env=sqlite \

观察

  • ↑eval/reward，以及每条 episode 的 tool_calls。

  • ↓truncated：轮数或 token 用尽的 episode 记 0 分。

实验

opd/configs/stage4_distill_reward.py

模仿教师，加上任务奖励

现在每个提示词采样 4 次。环境给每个最终答案打分（1 或 0），每条 episode 的奖励减去组内均值、再除以组内标准差，就得到一个序列级优势，加到它的每一个 token 上。教师项仍然叠加在上面，逐 token 计算。

两个信号的失效方式正好相反。教师可能会错，奖励可以纠正它。而当 4 个样本结果一致时，奖励就沉默了：zero_advantage_groups 报告这种情况出现的频率，在这些组里，教师项是学生唯一的学习来源。

关键参数

loss.teacher_coef = 1.0
loss.reward_coef = 1.0
loss.normalize_std = True   # GRPO; False = Dr. GRPO
train.samples_per_prompt = 4
train.prompts_per_step = 4
train.lr = 5e-5

观察

  • ↑reward（训练）和 eval/reward。
  • –zero_advantage_groups：奖励什么都没教的提示词占比。
  • –teacher_kl：随着奖励把学生拉向它自己的方向，可能趋平或略微上升。
python -m opd.main --config=opd/configs/stage4_distill_reward.py:mps \
    --config.model.init_checkpoint=runs/stage3/final --workdir=runs/stage4

实验

  • 练习：在训练过程中把 teacher_coef 从 1 退火到 0（在 trainer.train 里加几行）。这就是通往阶段 5 的桥梁。
  • --config.loss.normalize_std=False，比较奖励曲线。
  • 把 reward_coef 设为 3，观察 teacher_kl 是否上升。

opd/configs/stage5_grpo.py

GRPO：基于环境反馈的智能体 RL

没有教师。唯一的评分是最终答案对不对，而关于如何得到答案的唯一线索来自环境本身：SQL 错误信息、空的查询结果、计算器输出。省下教师的 16 GB 后，学生对每个提示词采样 8 条 episode。

现在每批 rollout 会喂给两次优化器更新。第二次更新所用的样本来自第一次更新之前的策略，因此概率比偏离 1，PPO 截断开始生效：留意 clip_frac。

关键参数

model.teacher = ""
loss.teacher_coef = 0.0
loss.reward_coef = 1.0
loss.clip_low = 0.2
loss.clip_high = 0.28    # DAPO clip-higher
loss.ref_kl_coef = 0.0   # try 1e-3
train.samples_per_prompt = 8
train.num_minibatches = 2
train.lr = 1e-5          # Tinker's math RL recipe

观察

  • ↑reward、eval/reward、各类型的奖励。
  • –entropy：快速塌缩到 0 说明策略停止了探索。
  • >0clip_frac：两个 minibatch 时较小但不为零。
  • –ref_kl（开启时）：与本阶段起点策略之间的 KL。使用新的 LoRA adapter 时，参考模型不占额外开销：它就是关掉 adapter 的同一个模型。

走出单机

先扩展规模，再在此基础上构建

opd/trainer.py 是为阅读而写的。要超越单个设备，opd/trl_train.py 会在 TRL 的 GRPOTrainer 上运行每个阶段配置，从而获得 vLLM 生成和多 GPU 训练。环境无需任何改动：它们已经遵循 TRL 的 environment_factory 约定（reset(**task)；其他每个公开方法都是一个工具）。

TRL 没有教师，所以 OPDTrainer 加了一个。它让 GRPOTrainer 照常采样并评分一批数据，向教师查询每个采样 token 的对数概率，然后把与 losses.py 相同的逐 token 优势交给 GRPO 的损失：reward_coef × A_task − teacher_coef × (log p − log q)。其余部分（截断代理目标、把工具结果从损失中 mask 掉、多轮工具循环）都是 TRL 自己的代码。

构建过程中踩过的坑

实战笔记

悄无声息的 top-k 采样

transformers 5.x 在你只传 do_sample=True 时会应用 top_k=50，而 Qwen3 检查点自带的生成配置是 temperature 0.6、top-k 20、top-p 0.95。截断后的样本并不来自你用来训练对数概率的那个策略。在一个很小的随机模型上实测：400 个单 token 样本在默认设置下恰好只有 50 个不同 token，用了 rollout.generate 中的覆盖之后超过 100 个。

重新渲染会改写历史

Qwen3 的对话模板会从过去的 assistant 轮次中删掉空的 <think></think> 块。如果从消息重建多轮 episode，得到的 token 会和学生实际采样的不同。所以 rollout 改为以 token 形式追加工具结果；chat_test.py 展示了两种行为。

bf16 会吞掉小的更新

bf16 只有 8 位尾数，比权重小约 1/256 的更新会被舍入掉。因此全参数微调在 bf16 autocast 下保留 fp32 主权重；LoRA 则冻结 bf16 底座，adapter 保持 fp32。

词表才是显存大户

在 Qwen3 的 151,936 词表上，一行 1,024 token 的 float32 logits 就是 622 MB。代码一次只计算一行的对数概率，并用 logits_to_keep 跳过共享提示词内的位置。

无偏不等于有用

在一对很小的玩具模型上，精确 KL 估计量在 30 步内把 KL 从 3.9 降到 2.3 nats，而单样本估计量在每步 64 token 时几乎不动，512 token 时从 3.9 降到 3.1。期望梯度相同，方差却天差地别。真实的 Qwen3 模型对起点比玩具模型近得多，方差也就更低。

结果一致的组什么也学不到

在二值奖励下，学生总能做对（或总做不对）的提示词，组优势为零。题目太简单或太难，RL 都会停滞。reward 曲线平坦时，第一个要看的指标就是 zero_advantage_groups。

同一家族不等于同一词表

token 级蒸馏比较的是相同 token id 的对数概率，所以 trainer 会拒绝不匹配的分词器。即使在同一家族内，不同检查点的输出层也可能填充得不一样（Qwen2.5-7B：152,064 行；Qwen2.5-0.5B：151,936 行），精确 KL 路径通过比较共享前缀来处理这一点。

KL 惩罚放在哪里很重要

GRPO 把 Schulman 的 k3 估计 KL(π ∥ ref) 加到损失上。它的值是对的，但对 log π 求导后，期望梯度对应的是 KL(ref ∥ π)，即覆盖质量（mass-covering）的方向。本仓库则像教师项那样把惩罚放进优势。losses_test.py 通过精确枚举验证了这两点。

截断即零奖励

轮数或 token 用尽的 episode 记 0 分，即使未完成的文本中已经出现了草稿 \boxed{}。如果 truncated 在上升，学生是因为太长而受罚，而不是因为答错。先提高预算，再去怪方法。
