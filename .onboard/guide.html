Post-training lab · Qwen3.5-9B teaches Qwen3.5-2B · Apple M5 Pro or one A100

Every token the student writes gets a grade.

This guide walks you through a from-scratch pipeline that takes a 2B model from on-policy distillation to a tool-using agent trained with RL. All five stages run the same loop: the student samples, a judge scores, the student updates. What changes is who the judge is and how often it speaks.

Start here

The one idea

Post-training methods differ in two ways: whose samples you train on, and how much feedback each sample carries. Supervised fine-tuning trains on someone else's text, so the student never sees its own mistakes. Reinforcement learning trains on the student's own samples, but a whole episode earns one number. On-policy distillation takes the best of both: the student writes, and a stronger teacher grades every token.

Supervised fine-tuningoff-policy (teacher's or dataset's)dense, per tokennot used

The bridge between the rows is one line of algebra. Sample yt from the student p and treat log q(yt) − log p(yt) as a reward. Its policy gradient is, in expectation, exactly the gradient of the per-token reverse KL, KL(p ∥ q). So distillation is RL with a dense reward the teacher computes for every token, and the same clipped policy-gradient loss serves all five stages. opd/losses_test.py checks this identity numerically (test_distillation_advantage_gives_reverse_kl_gradient).

Why reverse KL? It is mode-seeking: the student is punished for putting mass where the teacher puts little, and is not forced to cover everything the teacher might say. That suits a smaller student that cannot represent all of a larger teacher.

The same term appears once more. A KL penalty that keeps an RL policy close to where it started is this estimator with your former self as the teacher: ref_kl_coef · (log ref(yt) − log p(yt)), added to the advantage.

# opd/trainer.py, update(): the heart of every stage
advantages = config.loss.reward_coef * batch.task_advantages[:, None]
if batch.teacher_logp is not None:
  teacher_kl = old_logp - batch.teacher_logp          # log p - log q, per token
  advantages = advantages - config.loss.teacher_coef * teacher_kl
per_token, clipped = losses.clipped_policy_loss(
    logp, old_logp, advantages, config.loss.clip_low, config.loss.clip_high)
loss = (per_token * batch.action_mask).sum() / num_tokens

Where the memory goes

Weights at 2 bytes per parameter in bf16, language models only (both checkpoints also hold a vision tower, which the from-scratch trainer never loads): Qwen3.5-9B (8.95B params) ≈ 17.9 GB, Qwen3.5-2B (1.88B) ≈ 3.8 GB. LoRA rank 32 on every linear layer is roughly 34M trainable parameters; with fp32 weights, gradients and two Adam moments that is about 0.5 GB (the run log prints the exact count). Full fine-tuning keeps fp32 master weights, gradients and Adam state: 16 bytes per parameter, about 30 GB for 1.88B. The dashed line on the Mac rows is the GPU share macOS allows by default, roughly 75% of RAM (36 GB); the hatched “room” is what remains for activations, logits and KV caches.

Read the code in this order

Code map

  1. opd/losses.py: the math of every stage in about 150 lines. Read it first.
  2. opd/rollout.py: how an episode becomes one token sequence with an action mask.
  3. opd/chat.py: the Qwen3.5 chat format, tool schemas, tool-call parsing.
  4. opd/trainer.py: collate, score, update, train.
  5. opd/envs/base.py, then one environment such as calculator.py.
  6. opd/configs/base.py and the five stage configs: the only thing that differs between stages.

Outputs of every run land in --workdir: metrics.jsonl (one JSON line per step), samples.jsonl (decoded episodes, tool results wrapped in [env]…[/env]), config.json, and checkpoints step_N/ and final/. Read samples often. Most RL bugs are visible in the text before they are visible in a curve.

01

opd/configs/stage1_distill.py

Plain on-policy distillation

The student answers GSM8K grade-school math questions. The teacher reads each answer and reports, for every token, how likely it would have been to write that token. Nothing else: no reward, no tools, no reference answers in the loss. The answers are used only to measure accuracy on held-out questions, so you can watch accuracy rise from a signal that never mentions correctness.

Knobs

env = "gsm8k"
loss.teacher_coef = 1.0
loss.reward_coef = 0.0
train.samples_per_prompt = 1
rollout.max_turns = 1
train.lr = 1e-4      # LoRA (Tinker's OPD recipe)

Read

  • losses.token_logprobs: float32, one row at a time.
  • trainer.forward_logits: logits_to_keep skips prompt positions.
  • trainer.update: the teacher term in the advantage.
  • rollout.generate: the sampling overrides and why.
python -m opd.main --config=opd/configs/stage1_distill.py:mps --workdir=runs/stage1

Watch

  • ↓teacher_kl: mean per-token reverse KL on sampled tokens. The curve that defines this stage.
  • ↑eval/reward: greedy accuracy on 64 held-out questions.
  • –teacher_eval/reward: the teacher's accuracy, logged once. Your ceiling.
  • –entropy, completion_tokens: a sudden drop in either means the student found a degenerate shortcut.

Experiments

  • --config.loss.teacher_estimator=full: exact KL over the 152k vocabulary instead of one sample. Compare the teacher_kl curves, and the memory.
  • --config.model.student=Qwen/Qwen3.5-2B-Base: a base model has a much larger gap to close, so the effect is bigger.
  • On the A100: --config.rollout.enable_thinking=True with a longer token budget.
02

opd/configs/stage2_single_tool.py

Single-tool agent distillation

Now an episode has several turns. The student writes a <tool_call>, the environment runs it and answers with a <tool_response>, and the student continues. Those responses enter the context but are not the student's actions, so their action mask is 0. The teacher still scores every student token, including the tool name and the JSON arguments, conditioned on the tool results it sees in the same context.

Run one tool per experiment. Each one teaches something different: the calculator rewards knowing when mental arithmetic fails, SQL rewards reading error messages, JMESPath rewards exploring a document you cannot see.

Knobs

env = "calculator"   # or "sqlite", "json"
rollout.max_turns = 4
rollout.max_new_tokens = 256        # per turn
rollout.max_completion_tokens = 1024  # whole episode

Read

  • chat.encode_prompt: tool docstrings become JSON schemas in the system prompt.
  • chat.encode_tool_results: why tokens are appended, never re-rendered.
  • rollout._step: one turn, its tool calls, the mask.
  • envs/base.call_tool: failures become error messages, not crashes.
python -m opd.main --config=opd/configs/stage2_single_tool.py:mps --config.env=sqlite \
    --config.model.init_checkpoint=runs/stage1/final --workdir=runs/stage2_sqlite

Watch

03

opd/configs/stage3_multi_tool.py

Many tools, many turns, the student decides

All three tools are offered on every task. The task mix includes single-tool questions, questions that chain two tools (look up a payroll in SQL, then apply a raise with the calculator), and easy questions that need no tool at all. Choosing a tool is just more tokens, and the teacher grades those too: the "name" field of a tool call is where a wrong choice shows up as a large negative advantage.

MultiToolEnv is an empty class: it inherits the three tools, and the cooperative reset(**task) chain builds both the database and the JSON document.

Knobs

rollout.max_turns = 6
rollout.max_completion_tokens = 1536

  • ↑eval/reward/sql+calculator, eval/reward/json+calculator, eval/reward/sql+json.
  • ≈2eval/tool_calls/sql+calculator: about one call per tool.

04

opd/configs/stage4_distill_reward.py

Teacher imitation plus task reward

Each prompt is now sampled 4 times. The environment grades each final answer (1 or 0), and each episode's reward minus its group's mean, divided by the group's standard deviation, becomes a sequence-level advantage added to every one of its tokens. The teacher term stays on top, per token.

The two signals fail in opposite ways. The teacher can be wrong, and the reward corrects it. The reward is silent whenever all 4 samples agree: zero_advantage_groups reports how often, and in those groups the teacher term is the only thing the student learns from.

Knobs

loss.teacher_coef = 1.0
loss.reward_coef = 1.0
loss.normalize_std = True   # GRPO; False = Dr. GRPO
train.samples_per_prompt = 4
train.prompts_per_step = 4
train.lr = 5e-5

Watch

  • ↑reward (training) and eval/reward.
  • –zero_advantage_groups: share of prompts where the reward taught nothing.
  • –teacher_kl: may level off or rise a little as the reward pulls the student its own way.
python -m opd.main --config=opd/configs/stage4_distill_reward.py:mps \
    --config.model.init_checkpoint=runs/stage3/final --workdir=runs/stage4

05

opd/configs/stage5_grpo.py

GRPO: agent RL from environment feedback

No teacher. The only grade is whether the final answer is right, and the only hints about how to get there come from the environment itself: SQL error messages, empty query results, calculator outputs. Without the teacher's 16 GB the student samples 8 episodes per prompt.

Each rollout batch now feeds two optimizer steps. The second step trains on samples drawn by the policy before the first step, so the probability ratio moves away from 1 and the PPO clip starts to bind: watch clip_frac.

Knobs

model.teacher = ""
loss.teacher_coef = 0.0
loss.reward_coef = 1.0
loss.clip_low = 0.2
loss.clip_high = 0.28    # DAPO clip-higher
loss.ref_kl_coef = 0.0   # try 1e-3
train.samples_per_prompt = 8
train.num_minibatches = 2
train.lr = 1e-5          # Tinker's math RL recipe

Watch

  • ↑reward, eval/reward, per-kind rewards.
  • –entropy: a fast collapse toward 0 means the policy stopped exploring.
  • >0clip_frac: small but nonzero with two minibatches.
  • –ref_kl (when enabled): KL to the policy this stage started from. With a fresh LoRA adapter the reference costs nothing: it is the same model with the adapter switched off.
python -m opd.main --config=opd/configs/stage5_grpo.py:mps \
    --config.model.init_checkpoint=runs/stage4/final --workdir=runs/stage5

Experiments

  • Start from the original Qwen3.5-2B instead of stage 4: how much did distillation buy you in RL steps?
  • --config.loss.ref_kl_coef=1e-3 and compare entropy and reward.
  • Learning-rate sweep: 1e-5, 3e-5, 1e-4. RL is far more sensitive to it than distillation.

Beyond one machine

Scale it, then build on it

opd/trainer.py is written to be read. To go past one device, opd/trl_train.py runs every stage config on TRL's GRPOTrainer, which adds vLLM generation and multi-GPU training. The environments need no changes: they already follow TRL's environment_factory convention (reset(**task); every other public method is a tool).

TRL has no teacher, so OPDTrainer adds one. It lets GRPOTrainer sample and grade a batch as usual, asks the teacher for the log-prob of every sampled token, and hands GRPO's loss the same per-token advantage as losses.py: reward_coef × A_task − teacher_coef × (log p − log q). Everything else (the clipped surrogate, masking tool results out of the loss, the multi-turn tool loop) is TRL's own code.

uv pip install -e "trl[vllm]" --config-settings editable_mode=compat  # Linux + CUDA
python -m opd.trl_train --config=opd/configs/stage1_distill.py:a100 --use_vllm --workdir=runs/trl/stage1
accelerate launch -m opd.trl_train --config=opd/configs/stage1_distill.py:a100 --use_vllm --workdir=runs/trl/stage1

Things that bit while building this

Field notes

Silent top-k sampling

transformers 5.x applies top_k=50 when you pass only do_sample=True, and a checkpoint's generation config can truncate further (Qwen3's: temperature 0.6, top-k 20, top-p 0.95). Truncated samples are not from the policy whose log-probs you train on. Measured on a tiny random model: 400 one-token samples gave exactly 50 distinct tokens with defaults, over 100 with the overrides in rollout.generate.

Re-rendering rewrites history

Qwen3.5's chat template drops the empty <think></think> block from past assistant turns. Rebuild a multi-turn episode from messages and the tokens differ from what the student sampled. The rollout appends tool results as tokens instead; chat_test.py shows both behaviours.

bf16 swallows small updates

bf16 keeps 8 bits of mantissa, so an update smaller than about 1/256 of a weight rounds away. Full fine-tuning therefore keeps fp32 master weights under bf16 autocast; LoRA keeps a bf16 base frozen and its adapters in fp32.

The vocabulary is the memory hog

One 1,024-token row of float32 logits over Qwen3.5's 248,320-token vocabulary is 1.0 GB. The code computes log-probs one row at a time, and logits_to_keep skips positions inside the shared prompt.

Unbiased is not the same as useful

On a toy pair of tiny models, the exact-KL estimator cut KL from 7.1 to 4.1 nats in 30 steps at 64 tokens per step; the single-sample estimator only reached 5.6, and needed 512 tokens per step to reach 4.7. Same expected gradient, very different variance. Real Qwen3.5 pairs start much closer than the toy pair, which keeps the variance lower.

Groups that agree teach nothing

With binary rewards, a prompt the student always solves (or never solves) has zero group advantage. Too easy or too hard and RL stalls. zero_advantage_groups is the first metric to check when reward is flat.

Same family is not same vocabulary

Token-level distillation compares log-probs of the same token ids, so the trainer refuses mismatched tokenizers. Within a family, checkpoints can still pad the output layer differently (Qwen2.5-7B: 152,064 rows; Qwen2.5-0.5B: 151,936), which the exact-KL path handles by comparing the shared prefix.

Where the KL penalty goes matters

GRPO adds Schulman's k3 estimate of KL(π ∥ ref) to the loss. Its value is right, but differentiated through log π its expected gradient is that of KL(ref ∥ π), the mass-covering direction. This repo puts the penalty in the advantage instead, like the teacher term. losses_test.py checks both claims by exact enumeration.

Truncation is a reward of zero

An episode that runs out of turns or tokens scores 0, even if a draft \boxed{} appears in its unfinished text. If truncated climbs, the student is being punished for being long, not for being wrong. Raise the budget before you blame the method.
